# FloorFlow CVPR Experiment Structure v2

Status date: 2026-11-02. Status: frozen scoped release.

## Main Paper Structure

`paper/main.tex` contains the complete argument, four generated tables, two main
figures, worked examples, limitations, reproducibility, ethics, the LLM Usage
Statement, and references. It compiles to six pages with the official
`paper/cvpr.sty` template. `paper/supplement.tex` compiles to two pages and holds
the evidence-population table, outside contract, metric separation, statistics,
predicted behavior, failure taxonomy, held-out availability, and reproducibility
details.

## Canonical Tables

1. `paper/tables/main_oracle_anchor_v1`
   - 2,479 oracle edits, five operations, five repeated seeds.
   - Delta-IoU and Delta-MSE, exact outside layers, FP-Eval validity, and pooled
     raw/functional topology.
2. `paper/tables/main_predicted_reliability_v1`
   - val491 five-seed plausibility and fidelity.
   - 738-prompt development-exposed operation safety.
   - Older val191 semantic diagnostic with every failure retained.
3. `paper/tables/main_resource_and_ablation_v1`
   - Same-case Raster2Seq wrapper and editing-aware control.
   - Deterministic composition-policy arms and routing latency.
4. `paper/tables/main_external_context_v1`
   - HouseMind-E, Raster2Seq public anchor, typed graph, and predicted fidelity.
   - Population labels prevent cross-protocol leaderboard reading.

Markdown and LaTeX are generated by the same script. The Markdown files are the
binding release representation. No table is hand-edited after generation.

## Canonical Figures

1. `floorplan_protocol_overview_v1`: source state, typed change, outside domain,
   and evaluation axes.
2. `predicted_control_operation_panels_v1`: safety, plausibility, and semantic
   realization as separate panels.
3. `floorplan_failure_taxonomy_v1`: supported-prompt success/failure counts and a
   deterministic failed val191 case.
4. `floorplan_qualitative_cases_v1`: one oracle room-type positive and one failed
   predicted room-removal case.

`outputs/reports/floorplan_figure_case_manifest_v1.json` records case names,
roles, source arrays, selection rules, and failure reasons.

## Statistical Units

- Oracle intervals resample floorplans and average edits within a sampled
  floorplan. Repeated seeds are not independent plans.
- Paired controls use one mean difference per unique floorplan and Holm
  adjustment over five operations.
- The seed19 trace audit recomputes all 2,479 primary rows with zero IoU error.
- The composition analysis is a post hoc matched-budget audit of deterministic
  routing policies; it is not a new model comparison.
- Operation execution and abstention are counted separately from val191 semantic
  success.

## Evidence Boundaries

- Oracle controls are target-derived and non-deployable.
- Predicted val491 controls are target-free at inference and use validation rows.
- Operation prompts are development-exposed `test` rows, not held out.
- The val191 semantic diagnostic uses an older model and is not attributed to the
  selected predicted checkpoint.
- Raw `0.816701` and functional `0.997963` watertightness are distinct.
- HouseMind-E is cross-dataset context; Raster2Seq is a redrawing wrapper.
- Fresh held-out generalization is `optional_generalization_not_evaluated`.

## Rebuild and Verification

```bash
uv run python scripts/build_floorplan_submission_evidence_v2.py
uv run python scripts/build_floorplan_submission_tables_v2.py
uv run python scripts/build_floorplan_submission_figures_v1.py
(cd paper && latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex)
(cd paper && latexmk -pdf -interaction=nonstopmode -halt-on-error supplement.tex)
uv run python scripts/prepare_predicted_control_submission_freeze_v1.py \
  --mode existing_evidence_scoped \
  --output configs/floorplan_submission_evidence_freeze_v2.json
uv run python scripts/audit_floorplan_evidence_freeze_v2.py
uv run python scripts/build_floorplan_submission_artifact_v1.py
uv run python scripts/audit_floorplan_submission_integrity_v1.py
```

The final artifact manifest, submission checklist, and integrity report are
separate: local checks establish package consistency, while OpenReview
enrollment and upload require explicit user authorization.
