## 1. What the current protocol actually asks the model to do

The current FloorSet/Trinity protocol is **not RTL-to-GDSII generation**. It is a
block-level chip floorplanning protocol:

```text
areas + constraints + b2b/p2b netlist + fixed pins
    -> block positions and aspect ratios
    -> constraint refinement
    -> exact-area legalization
    -> official FloorSet score
```

The model scope is therefore four coupled decisions:

1. choose the global placement envelope;
2. choose cluster/MIB/boundary structure;
3. place each block and choose its aspect ratio;
4. route a legalized proposal through external EDA for downstream validation.

Position and shape are generated. Fixed shapes, preplaced positions, exact target
area and non-overlap are constrained. Ports are fixed conditioning inputs rather
than an action generated by the model. Orientation, halo/channel layout, PDN,
standard-cell placement, CTS, routing and signoff are absent or external.

## 2. Real design sequence and model locus

| Real design action | Current protocol visibility | Existing model path | Coverage |
|---|---|---|---|
| RTL synthesis | Block areas, pairwise b2b/p2b edges, pins; no standard cells | Typed encoder, pairwise graph messages | Partial |
| Floorplan setup | Block areas and reference bbox | Exact-area decode, L0 global state, bbox objective | Strong |
| IO/pin planning | Fixed pins and p2b incidence | L3 port tokens and alignment state | Conditioned, not generated |
| Macro position and shape | Positions and aspect ratios | L2 per-block flow trajectory | Strong |
| Macro orientation | Reference orientation only | None; adapter preserves reference | Not in protocol |
| Halo/channel spacing | External ORFS adapter only | Hard overlap projector plus external halo packing | Partial |
| Cluster/MIB/boundary repair | Native constraint fields | L1 structural state, refiner energies, final legalizer | Present, weak or seed-sensitive |
| PDN | External ORFS | None | External only |
| Standard-cell global placement | External ORFS `3_3_place_gp` response | Budgeted proposal response and reranking | External feedback |
| Standard-cell legal/detail placement | External ORFS | None | External only |
| CTS | External ORFS | None | External only |
| Global/detailed routing | Routed WL, overflow, DRC endpoints | None | External evaluator only |
| Signoff | Timing, power, area, DRC | None | External evaluator only |

This distinction prevents two common mistakes:

- adding a network head named after PDN, CTS, routing or STA without a learned
  action or matched data;
- strengthening a path that already exists before proving that the path is
  absent, weak or bypassed.

## 3. How the model realizes the in-scope actions

### Synthesis-derived conditioning

`graph_conditioned_features` creates block features from area, degree, fixed and
preplaced flags, MIB/cluster membership, boundary code, anchors and pin pull.
`GraphMessageBlock` sends pairwise b2b messages and pin-to-block messages.
`TypedGraphEncoder` pools these into global, structural, constraint and port
memory.

The representation is pairwise. FloorSet does not provide hyperedge training
labels, so a new hyperedge network would be a protocol shift. The gap remains
deferred until matched hyperedge data exists.

The typed graph is currently encoded once in `prepare_context`, then reused for
every flow step. The current block center, size and net span therefore do not
modulate b2b/p2b messages. This is a static-trajectory gap distinct from the
rejected A5 edge gate. The next trainable candidate is a sparse, zero-init
state-conditioned geometry relay inside the existing `GraphMessageBlock` path;
it must not recompute dense typed attention per ODE step.

### Floorplan setup and macro placement

`decode_boxes_batch` enforces the target block area exactly. The L0 state models
the global bounding box. The L2 state is the existing per-block flow trajectory.
`integrate_hierarchy_step` and `sample_hierarchy_flow` execute the ODE.

This is the correct place to strengthen global compactness or block placement.
It is not the correct place to add a generic routing head.

### Structural constraints and legality

`structural_membership` creates explicit cluster, MIB and boundary masks. The L1
state and constraint energies act on them. `project_hard_constraints` and the
conditioned projection plan enforce fixed/preplaced/overlap/MIB/boundary
constraints during sampling; final `scale_pack` restores exact area and legal
packing.

Grouping and MIB paths exist but have weak evidence. The next test should be a
matched necessity ablation, not another extra typed layer or scalar loss sweep.

### Ports

`_port_tokens` and the L3 alignment state encode fixed pin geometry and p2b
incidence. The model does not place IO or select orientations. A port direction
channel is absent from the current schema.

### Halo and channels

The external adapter can inflate/deflate macro boxes and pack with a halo. The
model sees ordinary overlap constraints, not halo or channel tokens. Add a halo
field only if failure attribution shows that this missing observation causes the
error.

## 4. Downstream feedback is an evaluator unless explicitly budgeted

ORFS global placement can produce a pre-route response for a legalized macro
proposal. It is represented as:

```text
generated proposal -> legalization -> 3_3_place_gp -> analytical response
    -> proposal reranking or bounded test-time feedback
```

The response is a physical EDA computation with measurable wall time. It is not
a free model feature. It may be used only when:

1. candidates are generated under a fixed NFE/refiner budget;
2. legalization and response cost are counted;
3. the response is compared with the existing p2b ranker on fresh proposals;
4. routed WL, congestion, timing, power and DRC stay outside selection and are
   certified only after selection.

Only a validated response can later be distilled into the existing L1/L2 path.
The rejected scalar routing proxy and unvalidated energy combination are not
revived.

## 6. Required procedure before any new module

For each proposed enhancement, record all of the following in
`chipstodo.json` and the candidate registry:

1. real design action and protocol-visible inputs;
2. whether the action is generated, constrained, conditioned, externally
   evaluated or out of protocol;
3. exact existing state/token/operator/stage to extend;
4. matched probe showing the path is absent, weak or bypassed;
5. smallest architecture-aligned change;
6. expected causal metric and falsification condition;
7. frozen-subset quality gate and operator-latency gate;
8. retained negative result if the mechanism fails.

No new module is admitted if its only justification is a generic name such as
"routing head", "timing block" or "PDN encoder".

## 7. Immediate execution decision

The current execution blocker is not another architecture module. It is to
complete the
matched-flow analytical response pilot and determine whether a deployable
downstream response contains information that the existing p2b path lacks.

Architecture work resumes only after that decision:

- if the response ranks better, extend the existing proposal/search path first;
- independently run a representation probe for the missing dynamic graph path;
- if the response has no incremental value, test the existing L1 structural
  path with a matched ablation;
- if a real action is missing but has no matched data, retain it as a documented
  protocol boundary rather than inventing a head.
